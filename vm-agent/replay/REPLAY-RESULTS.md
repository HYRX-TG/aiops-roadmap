## Cloudflare 2019-07-02 全球故障（WAF 正则回溯耗尽 CPU）

- 来源（官方复盘）：https://blog.cloudflare.com/details-of-the-cloudflare-outage-on-july-2-2019/
- 真实根因（跑前固定）：13:42 部署的新 WAF 托管规则含灾难性回溯正则（.*(?:.*=.*)），在真实请求体上指数级回溯，耗尽所有 HTTP 服务核心 CPU；叠加因素：数周前的 WAF 重构移除了 CPU 过度使用保护、SOP 允许规则不经灰度直接全球推送、回滚需要完整重跑两次 WAF 构建、控制面与数据面同链路导致修复工具自身不可用。
- 决定性步骤（跑前固定；➖=通用样板不计分）：
  1. ✅ 按组件拆分 CPU 数据，定位到是 WAF 进程在吃 CPU（而不是泛泛的'CPU 高'）
  2. ✅ 把 CPU 饱和起始时间与 13:42 的 WAF 规则部署做时间关联（变更关联）
  3. ➖ 先查最近变更/发布，再怀疑攻击或容量（攻击假设是红鲱鱼）
  4. ❌ 识别控制面与数据面同链路受损，需要带外通道/紧急开关（全局关闭 WAF）

## Meta 2021-10-04 全球故障（骨干命令误断 + DNS 自动撤回 BGP）

- 来源（官方复盘）：https://engineering.fb.com/2021/10/05/networking-traffic/outage-details/
- 真实根因（跑前固定）：一条评估骨干容量的维护命令误将骨干网全部连接断开（审计工具 bug 未拦截）；数据中心孤立后，DNS 服务器按安全设计撤回 BGP 广播（本该屏蔽单点不健康，却因全部同时触发而放大为全局不可达）；恢复受阻于内部工具与带外通道同样依赖已故障的网络/DNS。
- 决定性步骤（跑前固定；➖=通用样板不计分）：
  1. ✅ 先分层定位：解析失败（DNS 层）vs 路由不可达（BGP 层）vs 应用错误——本例是名字根本解析不了
  2. ✅ 从外部视角检查自己前缀的 BGP 广播是否被撤回（不只看内部监控）
  3. ➖ 把故障起始时间与维护窗口的命令/变更关联（骨干维护命令）
  4. ✅ 识别恢复路径自身受损：内部工具与带外访问依赖同一套已故障的系统，需要带外/物理通道
  5. ✅ 识别'保护机制'变成了放大器：DNS 不健康即撤回路由的设计在全部同时触发时适得其反

### 平台原始输出（逐字）

**根因判定**：关联到近期运维操作（剧本《运维变更/操作事故（命令执行类根因）》）：维护人员 于 15:39 在 骨干网 执行「例行维护中执行评估全球骨干容量的命令（实际断开了骨干网全部连接）」（无变更单）。意图正确、参数/目标错误的操作类根因，必须先核对操作实际影响面。

**置信度**：medium · **大脑**：rule

**排查链**：
- [拉运维操作审计（时间线关联命中）] 维护人员 于 15:39 在 骨干网 执行：例行维护中执行评估全球骨干容量的命令（实际断开了骨干网全部连接）（无变更单）
- [拉运维操作审计] 操作者、命令原文、目标主机/子系统、是否在维护窗口内
- [对比意图与实际影响面] 实际命中对象数远超预期 → 基本可判定为参数/目标错误
- [确认可回退性与恢复路径] 可回退操作 + 有回滚预案 → 尽快回退；不可回退 → 评估重建耗时
- [冻结后续同类操作] 同模式操作在窗口期内被冻结
- [分层定位（DNS / BGP / 应用）] SERVFAIL=解析层失败；IP 通但域名不通=DNS 记录/权威服务器问题；IP 也不通=路由/BGP 层
- [从外部视角查自己前缀的 BGP 广播] 前缀广播消失/大幅减少 → BGP 层被撤回
- [对照维护窗口与变更] 故障起始时间与网络变更/维护命令吻合
- [评估控制面与带外通道] 控制面同链路受损 → 必须走带外；自动保护被同时触发 → 先隔离放大器

**验证命令**：
- `ops-audit query --since 60m  # 确认误操作后无同类操作再次执行`
- `对比操作前后子系统容量/错误率曲线，确认回到操作前水位`
- `核对实际影响对象清单与变更单声明的一致性`
- `dig +short <domain> @公共解析器  # 解析恢复`
- `RIPEstat 外部视角确认前缀广播已恢复`
- `从多个地理位置的探测节点确认可达性`
- `对比故障前后的路由表/广播数量`

**🟢 可自动处置**：回退该操作（有回滚脚本/配置备份时）；冻结同模式操作窗口（防拉锯）；切换客户端/服务到备用 DNS 解析器；临时停用'不健康即撤回'自动保护（单点）
**🔴 需审批处置**：大面积回滚/批量恢复（rolling·操作方负责人 + SRE on-call）；从备份恢复数据（full·数据 Owner + SRE on-call）；修改 BGP 广播/路由策略（full·网络负责人 + SRE on-call）；重启/替换骨干路由器、动物理链路（full·网络负责人 + 云平台审批）
